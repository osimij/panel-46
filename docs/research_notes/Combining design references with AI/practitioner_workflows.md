## 1. Step-by-step workflows people describe for going from several references or a mood board to a new design

### Takeaway
Nobody credible reports success from dropping several screenshots straight into a build prompt; the workflows that people report as working all add a middle step, and the four middle steps that recur are (a) a written brief that gives each reference one job, (b) extraction into tokens / DESIGN.md / a style page before any page is built, (c) making 3–10 directions, picking, then remixing the picks, and (d) increasingly in 2026, choosing an image comp first and coding to match it. The only controlled test found (one designer, about nine runs) says the written "what to take from each" lines changed the result more than attaching the references did.

### Cited Findings

**A. One job per reference, written down (the only direct test of two references)**
- **[SHOWN]** Heyn Studio (one-person design studio, Korea) ran the same request four ways in Claude Code (October 2026, model not named), an Instagram post for a café as a single HTML file. Request only: clean but template-like. Two references attached with no words: Claude treated both as equally binding and mixed them at random (dark background, artwork covering the headline); on another run it nearly copied one reference's dark card. References plus a few lines on what to take from each: the brand tone came through. Plus a real photo and one fix: ready to post. Result images are shown per condition. Posted 3 Nov 2026 (year inferred from the author's join date; the post says each level was re-run for "9 runs", which does not quite add up). — [DEV Community](https://dev.to/heynstudio/i-ran-the-same-claude-design-request-4-times-only-the-reference-hand-off-changed-4fnb)
- **[SHOWN]** Same author's recipe: two or three references with different roles (one for overall tone: color, background, mood; one for type; one for layout), more than three blurs the result; a separate "take" list and "don't take" list (e.g. take the paper background and the single giant word; don't take the layout or mockup elements); a few hard rules (largest element, minimum gaps and margins, limits on emoji/gradients/shadows); when something is off, fix one or two things and say to keep everything else. — [DEV Community](https://dev.to/heynstudio/i-ran-the-same-claude-design-request-4-times-only-the-reference-hand-off-changed-4fnb)

**B. Research → compare → one primary + narrow borrows → "reference lock" → build → check (Refero skill)**
- **[DOC][VENDOR]** Refero's open-source skill (MIT, v1.0.3, repo created 5 Feb 2026, last pushed 15 Oct 2026, ~350 stars) is the most explicit published method for several references. Steps: write a short brief; search 3–5 different visual angles (one broad aesthetic, one category, one known brand); open 3–4 full style references; compare what each contributes; choose one primary foundation and borrow one or two specific details from the others; write a "reference lock" (primary direction; 3–5 traits that must survive; the 1–2 borrowed details; role rules for tokens; media strategy; a reject list of the defaults/averages that would collapse it; token commitments); turn it into a "decision ledger" table (decision, source, source rule, why) where any major choice with no source is removed; build; compare the render against the lock. — [refero_skill SKILL.md](https://github.com/referodesign/refero_skill/blob/HEAD/skills/refero-design/SKILL.md)
- **[DOC][VENDOR]** Its worked example (a pricing page) uses four style references: the "data infrastructure" one is primary; the other three each give one named thing (type hierarchy, section spacing, accent discipline); the reject list names the look the model would otherwise drift to (cream canvas, serif hero, clay accent). — [example-workflow.md](https://github.com/referodesign/refero_skill/blob/HEAD/skills/refero-design/references/example-workflow.md)
- **[DOC][VENDOR]** For bigger visual jobs the skill defaults to three reference-locked directions (each with its own primary source, kept traits, borrowed details, rejects), then stops and asks the person to choose; the chosen one becomes the build and QA target. — [visual-workflow.md](https://github.com/referodesign/refero_skill/blob/HEAD/skills/refero-design/references/visual-workflow.md)

**C. References → tokens / design system / style page → pages**
- **[CLAIMED]** Take 3–5 screenshots of a target design, ask regular Claude for a JSON design system (with attention to gradient directions, shadow specs, hover states), paste that JSON into Claude Code and build the homepage first "strictly following" it. The example given copies one site (Cursor's landing page), not several. 26 Jun 2025. — [Implicator](https://www.implicator.ai/how-to-build-professional-web-designs-using-claude-code/)
- **[CLAIMED]** Steven Gonsalvez: tokens into DESIGN.md first, lock one component library, build components in Storybook, then pages, then wrap it all in a brand skill; each layer constrains the next. No pictures or numbers. 10 Jul (2026 inferred). — [DEV Community](https://dev.to/stevengonsalvez/the-ai-design-stack-three-skills-and-a-workflow-that-stops-the-slop-5a07)
- **[CLAIMED, worked example]** PostHog's guide (Lior Neu-ner, 16 Jun 2025; tools: Lovable, v0, Bolt): job-to-be-done sentence → study three competitors and write for each a list of what works and a list of what does not, attaching screenshots by filename with a one-line note → wireframe → 4–6 colors mapped to roles as JSON → design system → check against six principles. It walks through one app and lists the flaws of the first result. All three references sit in one prompt; no merge rule beyond keep/avoid lists. — [PostHog newsletter](https://newsletter.posthog.com/p/an-engineers-guide-to-vibe-design)
- **[CLAIMED]** Papercraft (Jhan Gonzales, 18 Apr 2026; Claude Code + Paper MCP + shadcn/ui): build a mood board in Paper from reference images and drawn components; `/papercraft init` reads it and writes a DESIGN.MD plus a visible token frame on the canvas; `/papercraft preview` renders components in that theme. How several images become one system is not explained. — [Contra](https://contra.com/community/KoIGOR5X-streamline-design-workflow-with-papercraft-integration)
- **[DOC]** my-design-flow plugin (hye-on, v0.1.0, Apr 2026): PRD check → reference collection (the user supplies them; no scraping) → three mood-board directions → user picks one and the others are deleted → DESIGN.md tokens → preview screens → token-level feedback loop. — [ClaudePluginHub](https://www.claudepluginhub.com/plugins/hye-on-my-design-flow)
- **[DOC]** moodboard-creator skill (davepoon): table of sources with what to extract from each and why → extract colors/type/patterns/mood → a versioned mood-board document that ends with a "what to avoid" list → user review → at most 3–4 rounds → final. No rule for conflicts between sources. — [ClaudePluginHub](https://www.claudepluginhub.com/skills/davepoon-frontend-design-pro-plugins-frontend-design-pro/moodboard-creator)
- **[VENDOR][CLAIMED]** Superdesign's prompt pack (21 Jun 2026): an "extract a reference" prompt that tells Claude not to copy pixel for pixel, to turn the screenshot into reusable rules, and to append them to DESIGN.md as a named reference section; a dashboard prompt that takes structure, density and type pairing from the reference but color from DESIGN.md tokens; a screenshot-compare loop that asks for a specific diff. — [Superdesign](https://superdesign.dev/blog/claude-code-design-prompts)
- **[SECONDHAND]** Design OS (Brian Casel, Builder Methods, first released Dec 2025): product planning → design system (colors, type, shell) → section design → export of prompts for a coding agent. — [Builder Methods](https://buildermethods.com/design-os), [GitHub](https://github.com/buildermethods/design-os)
- **[SECONDHAND]** A "kitchen-sink" skill makes one page with every component the source of truth; production pages may only use what that page defines. — [skills.lc](https://skills.lc/Baphomet480/claude-skills/baphomet480-claude-skills-skills-kitchen-sink-design-system-skill-md)

**D. Go wide, pick, then remix the picks**
- **[CLAIMED]** Nate Parrott (the Anthropic designer who built Claude Design; 24 Jul 2026): set the look first (fonts and colors, a mood board of images, or have Claude propose font/color pairings); ask for about ten options and expect one or two to be good; then ask for five more that combine option B with a little of option D; ask for wireframes when you want Claude to think about structure, not looks. No scoring method; the designer's eye chooses. — [Claude blog](https://claude.com/blog/how-the-product-designer-who-built-claude-design-uses-it-to-explore-ideas-before-building-them)
- **[CLAIMED]** Dianne Alter (The Design Project, 30 Apr 2026): five wireframe variants is the right number to compare; she picks one, she does not merge. Claude Design is for concept exploration before Figma; high fidelity there is weak. — [The Design Project](https://designproject.io/blog/claude-design-workflow/)
- **[CLAIMED, worked example]** Chase Hannegan (23 Jul 2026; Claude Code with Impeccable, taste-skill, Higgsfield MCP, 21st.dev): keep a library of inspiration screenshots (he had Claude Code build a small app that tags them and writes a brief per item); ask Claude to look at the library, pick five aesthetic families and build one site in each; choose one; ask for three variations; choose; generate four hero images; finish with live tweak controls. The article walks through each round on a made-up product. — [Chase AI](https://chaseai.io/blog/fix-claude-code-web-design-ai-slop)
- **[SHOWN, on video]** Claire Vo (How I AI, 22 Apr 2026): in Claude Design, keeping the default three variations and comparing was faster than describing layout wishes up front. — [ChatPRD](https://www.chatprd.ai/how-i-ai/claude-design-and-gpt-images-2-building-landing-pages-slides-and-brand-kits)
- **[CLAIMED]** Muzli roundup (Eyal Zuri, 27 Apr 2026): ask for three versions with a different direction each; Claude Design keeps every version and pieces from different variants can be mixed; asking it to save the current state before trying a wholly different approach keeps the original. — [Muzli](https://muz.li/blog/claude-design-one-week-in-hacks-best-practices-tips-from-real-world-use/)
- **[SECONDHAND]** Claude Code `/design` (research preview from 17 Aug 2026, per an independent review dated 23 Aug 2026 that notes Anthropic had not published its own announcement): one HTML page with several editable artboards; pick one, tweak, then Claude changes the real project. The review says it does not pick up a project's design system by itself and is token-hungry, and says nothing about feeding it reference images. — [AIToolsReview](https://aitoolsreview.co.uk/insights/claude-code-design-skill)
- **[DOC]** Impeccable's new-work playbook: the agent derives seven candidate visual worlds from the audience's own culture, a script deals which ones reach the user (to stop the agent always ranking the same one first), the user sees one committed direction plus up to three challengers and a permanent option to take the plain category-standard look instead, and locks one. — [new-work-world.md](https://github.com/pbakaus/impeccable/blob/HEAD/.agent/skills/impeccable/reference/new-work-world.md)

**E. Picture first, then code to match the picture**
- **[VENDOR][CLAIMED]** Jason Zhou (AI Builder Club, 5 Jul 2026): concept with an image model (he says Nano Banana Pro can blend up to 14 input images, e.g. three references plus a logo into one mockup), then several standalone HTML mockups, then convert the winner to the real app one component at a time, with cheap snapshots to roll back. Full prompts are paywalled. — [AI Builder Club](https://www.aibuilderclub.com/blog/vibe-design-ai-ui-workflow)
- **[CLAIMED]** paddo.dev (26 Nov 2025; Claude Code with Opus 4.5 + Gemini 3 Pro image): a slash command generates a mockup, the author reacts ("too basic"), then Claude builds it. His caution: the mockup is a direction, not a spec, and design-system coherence still needs decisions. — [paddo.dev](https://paddo.dev/blog/nano-banana-ux-design-workflow/)
- **[DOC]** taste-skill's image skills (Oct 2026): generate the design image first, one large image per section (never one board for the whole page), keep one palette across all, analyse them, then implement to match; unclear sections are regenerated as fresh standalone images, not cropped. — [image-to-code SKILL.md](https://github.com/Leonxlnx/imagegen-skills/blob/HEAD/skills/image-to-code/SKILL.md), [imagegen-frontend-web SKILL.md](https://github.com/Leonxlnx/imagegen-skills/blob/HEAD/skills/imagegen-frontend-web/SKILL.md)
- **[DOC]** Impeccable: once a comp is approved it is treated as a measured spatial contract, not a mood board; the playbook states that models reliably believe their HTML/CSS recreation of an image succeeded when it did not, so it measures regions of the comp and gates the build on those measurements. — [new-work-comp.md](https://github.com/pbakaus/impeccable/blob/HEAD/.agent/skills/impeccable/reference/new-work-comp.md)

**F. Copy one well, then move away from it**
- **[CLAIMED, worked example]** Chase Hannegan's "7 levels" (27 Mar 2026): level 3 is 5–10 screenshots of different sections of one reference site plus its URL; level 4 is cloning its HTML/CSS/JS as a foundation (he frames it as a template to learn from), with the warning that stopping there is just copying; originality comes later from swapped components, custom images and visual editors (Stitch, Pencil, Paper). He does not describe a method for combining several sites, although his example ends up drawing on three sources. — [Chase AI](https://chaseai.io/blog/7-levels-building-elite-websites-claude-code)

**G. Tool-by-tool notes**
- **Claude Design** **[DOC]**: accepts screenshots of existing designs, competitor products, wireframes and visual inspiration, documents whose style to replicate, and a linked codebase; suggests asking for 2–3 alternative layouts; several design systems can be kept and Claude checks its output against the chosen one. No guidance on how many references or how to label them. (Help page undated; mentions Oct and Dec 2026 dates.) — [Claude Help Center](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)
- **Figma Make** **[DOC]**: say whether an attachment is a 1:1 build target or style inspiration; with several attachments say they are inspiration, not to be rebuilt; attach frame by frame for complex designs; up to 10 files per prompt but one or two at a time for exact builds. — [Figma Help](https://help.figma.com/hc/en-us/articles/31304529835671)
- **v0** **[DOC]**: a screenshot with no words is replicated closely (layout, colors, components); adding words like *as a guide* makes v0 produce its own take in the site's existing style; say which part of the image to use. Updated 3 Nov 2026. — [Vercel Academy](https://vercel.com/academy/v0-foundations/enhance-design-with-screenshots-and-versions)
- **Lovable** **[DOC]**: name one style direction, use its keywords and stay consistent across sections; save the direction into project instructions. — [Lovable docs](https://docs.lovable.dev/prompting/prompting-library)
- **Stitch** **[SECONDHAND]**: since March 2026 an infinite canvas that takes images, text or code as context, with an agent manager for several directions at once; one guide says a competitor screenshot or sketch can be dragged in as a reference. No source confirms a "blend several images" feature. — [Neowin](https://www.neowin.net/news/google-updates-stitch-with-vibe-design-and-infinite-ai-canvas/)
- **Mobbin MCP + Claude Code** **[CLAIMED]** (Dianne Alter, 28 May 2026): describe the page, attach a screenshot of its current state, ask for inspiration with a link to each example, push back on irrelevant ones, then ask for a low-fidelity in-repo mockup. First try came back too high-fidelity, in dark mode, ignoring the design system. — [The Design Project](https://designproject.io/blog/mobbin-mcp-design-inspiration/)
- **Aura / Meng To** **[SECONDHAND]**: remix a look in Variant or Aura, extract a Design.md, prompt with the HTML alongside it for fidelity (the md is the recipe, the HTML the finished dish), generate locally. From a third-party summary that would not load. — [summary page](https://ccm-design-engineer.netlify.app/summaries/design-md-ai-s-blueprint-for-consistent-custom-des-summary)

### Inferences
- The step that matters is turning pictures into a short written allocation ("this one gives X, that one gives Y, none of them gives layout") before anything is built. Heyn Studio's test and the Refero lock are the same idea at different sizes.
- The successful recipes are asymmetric: one reference (or one chosen direction) leads and the others each add one narrow thing. No source describes an even three-way blend that worked.
- "Wide then narrow" and "remix the picks" move the mixing from the references to the outputs: the person combines things the model already made coherent, which is easier for the model than combining raw references.
- For an assistant that writes single HTML pages and can look at its own renders, workflows B, D and the HTML-mockup half of E need no extra tools; the image-comp half of E needs an image model.

### Gaps
- No write-up found of anyone giving Claude 4+ labelled references from a personal library and reporting what happened. Heyn Studio stops at two.
- No source compares "one image at a time across turns" with "all at once".
- Stitch, Subframe, Magic Patterns, Cursor: nothing found on several references specifically (Magic Patterns' docs page returned only how to @-mention a file).
- X threads and Reddit posts could not be read, so practitioner reports there are missing.

## 2. DESIGN.md and design-token approaches, and whether anyone merges them

### Takeaway
DESIGN.md is now the common carrier for "the look" (Google's open spec, a 100k+-star community collection, extraction skills for sites and screenshots), but the spec, the collections and the extractors are all one-source-in, one-file-out; I found no tool or documented method that merges two DESIGN.md files. Where people do combine, they do it by hand with one of three rules: one primary plus bounded borrows with token roles kept (Refero), separate named reference sections inside one file (Superdesign), or a split by axis (layout from a reference, color from the tokens).

### Cited Findings
- **[DOC]** Google open-sourced the draft DESIGN.md spec on 21 Apr 2026 (Cassia Xu, Google Labs) so design rules can move between Stitch projects and other tools. — [Google blog](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-design-md/)
- **[DOC]** The spec is "alpha": YAML tokens (normative) plus markdown prose (how to apply them), eight sections in fixed order (Overview, Colors, Typography, Layout, Elevation & Depth, Shapes, Components, Do's and Don'ts), and a CLI with lint, diff (token-level changes between two files), export (Tailwind, DTCG) and spec. There is no extend/import/merge mechanism; token references resolve only inside one file. ~28.9k stars on 16 Nov 2026. — [google-labs-code/design.md](https://github.com/google-labs-code/design.md)
- **[DOC]** VoltAgent's awesome-design-md: 84 files on 16 Nov 2026, ~127.7k stars, each with nine sections (adds Responsive Behavior and an Agent Prompt Guide) and a preview HTML. Usage is one file at a time: copy a site's file into the project and ask for a page that looks like it. Nothing on combining. Disclaimers say the values are publicly visible CSS and no ownership is claimed. — [VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md)
- **[SECONDHAND]** Sources disagree on the section count (Google's eight, the collection's nine, and a "five-section" Stitch skill format). — [search summary of Stitch skill listings](https://tessl.io/registry/skills/github/google-labs-code/stitch-skills/design-md)
- **[SECONDHAND]** webdesignhot.com hosts per-brand DESIGN.md files and pairwise diff pages (e.g. 78 token-level differences between two systems) with exports to Tailwind/CSS/DTCG/Figma variables. It compares; it does not blend. — [webdesignhot](https://www.webdesignhot.com/design.md/remix-run/diff/linear/)
- **[SECONDHAND]** Extraction from a live site or screenshots: jezweb's design-system skill (Playwright + HTML inspection → DESIGN.md), html-to-design-md (for several pages: shared tokens first, then page-specific variants), Dembrandt (design lint, DTCG export, DESIGN.md), sleek-ui's design-extractor, and Google's stitch-skills (from Stitch screens or from source code). — [skills.sh](https://www.skills.sh/jezweb/claude-skills/design-system), [Skillselion](https://skillselion.com/skills/aaione/html-to-design-md), [TypingMind](https://www.typingmind.com/skills/dembrandt-extract-design), [skills.sh](https://www.skills.sh/luongnv89/sleek-ui/design-extractor)
- **[DOC][VENDOR]** Refero "Styles" are DESIGN.md-like references extracted from real marketing/product pages (a visual thesis, tokens, type, layout, section rhythm, imagery treatment, do/don't rules); a Japanese review (19 Sep 2026) counts 1,200+ sites. The skill's merge rules: a token's role is part of the token (a CTA-only color stays CTA-only, code-syntax colors stay inside code, decorative gradients stay decorative), and when styles are combined each source owns a bounded area (one owns canvas and type, another the code-window treatment, another the primary CTA). — [SKILL.md](https://github.com/referodesign/refero_skill/blob/HEAD/skills/refero-design/SKILL.md), [anti-ai-slop.md](https://github.com/referodesign/refero_skill/blob/HEAD/skills/refero-design/references/anti-ai-slop.md), [note.com review](https://note.com/ai_driven/n/nd9c9e8e95cc3?hl=en)
- **[VENDOR][CLAIMED]** Superdesign: each extracted reference is appended to DESIGN.md as its own named section; pages then say which reference anchors layout while tokens supply color. — [Superdesign](https://superdesign.dev/blog/claude-code-design-prompts)
- **[SHOWN]** Repaint (Ben Shumaker, 9 Apr 2026) compared tactics on one landing-page brief: pre-set colors and fonts cut color mistakes but layouts stayed the same; a design-skill prompt swapped one overused font for another; reference images were the first tactic that produced layouts outside the model's usual two or three; code/style templates raised quality but made everything look alike. — [Repaint](https://repaint.com/blog/picture-is-worth-a-thousand-tokens)
- **[VENDOR][SHOWN]** Banani (Vlad Solomakha; dated 26 Jul 2026 in the byline, 22 Oct 2026 in metadata) says designers in 2026 reference a design.md more than a UI picture; in its test, giving Claude Design (Opus 5 and Fable 5) Anthropic's own design file with a "do not deviate from the tokens" instruction produced screens that looked like Anthropic's. One brand's file in, that brand's look out. — [Banani](https://www.banani.co/blog/opus-5-vs-fable-5-at-ui-design)
- **[SHOWN]** Claude Design builds a design system from a repo, design files or uploads; Claire Vo's import from one public homepage took about five minutes and wrongly leaned to italic serif headings, which she corrected (22 Apr 2026). Muzli calls the brand kit the highest-leverage first session; the help page warns the import is only as good as its source. — [ChatPRD](https://www.chatprd.ai/how-i-ai/claude-design-and-gpt-images-2-building-landing-pages-slides-and-brand-kits), [Muzli](https://muz.li/blog/claude-design-one-week-in-hacks-best-practices-tips-from-real-world-use/), [Claude Help Center](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)
- **[DOC]** Impeccable takes the opposite order for brand-new looks: DESIGN.md is written at the end from the built result, on the grounds that a rulebook written first gets defended against reality. It also notes that prose descriptions of a design system drift while pixel references do not, so it anchors new comps on a screenshot of an existing page. — [new-work.md](https://github.com/pbakaus/impeccable/blob/HEAD/.agent/skills/impeccable/reference/new-work.md)
- **[DOC]** Figma Make kits: a Guidelines.md travels with library styles; Figma recommends letting Make draft it and then reviewing, and adding full code snippets where token syntax is tricky. — [Figma developer docs](https://developers.figma.com/docs/code/bring-your-design-system-package)
- **[DOC]** A community mood-board skill (ussumant, 23 Oct 2025, 7 stars) outputs one "aesthetic prompt" with hex codes, fonts, spacing and an avoid list from 3–7 examples, and tells users to choose examples with shared visual DNA and not to mix clashing aesthetics. That is avoidance of the merge problem, not a solution. — [GitHub](https://github.com/ussumant/design-theme-generation-skill)

### Inferences
- A DESIGN.md is already split by facet (color, type, layout, shapes, components), so a hand-made "merged" file that names a different source per section is a natural fit, but nobody has published one or tested it.
- Tokens carry color and type reliably and carry layout and imagery poorly (Repaint's result; Refero's warning about image-led styles collapsing to text). A merge done only at token level will lose whatever the layout or imagery reference was chosen for.
- "Design system first, pages second" is widely advised but its evidence is thin: the write-ups that show results (Repaint, Banani) show that a token file gives consistency and brand match, not originality.
- The `diff` command and the diff sites suggest a cheap check: after a build, diff the result's tokens against each source to see whether one source swallowed the rest.

### Gaps
- No source describes merging two or more DESIGN.md files, automatically or by a written procedure, with results.
- Stitch's own docs on generating a DESIGN.md from a URL or image could not be read (JavaScript-only page); the claim that it can comes from secondary write-ups.
- No data on how accurate screenshot-to-token extraction is (Claire Vo's serif mistake is one anecdote).

## 3. Skills and prompt packs for taste, and what they say about references

### Takeaway
The big taste skills (Anthropic's frontend-design, Impeccable, taste-skill, UI/UX Pro Max) are built to push the model off its defaults and say almost nothing about references a person brings; only Refero's skill has rules for several references. One hands-on test (Opus 5.5, Oct 2026) found the skills alone did not remove the "AI-made" look and a real reference did, and three independent sources note that the anti-default lists have themselves produced a second default look (cream, serif, terracotta).

### Cited Findings
- **[SHOWN]** Anthropic's blog (Applied AI team, 12 Nov 2025) explains generic output as "distributional convergence" (safe choices dominate training data) and fixes it with a roughly 400-token aesthetics prompt covering typography, color/theme, motion and backgrounds; shows before/after pairs for five page types. Its only nod to outside sources is a line about drawing on IDE themes and cultural aesthetics. Nothing on reference images. — [Claude blog](https://claude.com/blog/improving-frontend-design-through-skills)
- **[DOC]** The same snippet sits in Anthropic's current prompting guide (which lists models through Claude Fable 5.2; the frontend paragraph itself still names Opus 4.5/4.6). It admits the model re-converges on new favorites (it names one font) and asks for variation across light/dark, fonts and aesthetics. The guide's vision section adds that letting Claude crop or zoom into image regions gives a consistent lift on image tasks. — [Claude prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
- **[DOC]** The current frontend-design SKILL.md (anthropics/skills, read 16 Nov 2026) has changed shape: act as a studio lead whose client rejects templated work; ground choices in the subject's own world; write a compact plan first (4–6 named hex colors, typefaces with roles, layout in one-sentence descriptions and ASCII wireframes, principles), review the plan against the brief and replace anything that reads as default, then build; spend boldness in one place; self-critique from screenshots. It lists its own tells, including the cream + serif + terracotta look, and says the brief's words always win. - **[VENDOR][CLAIMED]** Superdesign: the frontend-design skill gives heuristics, not a visual source of truth, so output plateaus, and it is weaker on dense product UI (tables, states). — [Superdesign](https://www.superdesign.dev/blog/claude-code-ui-design)

### Inferences
- Taste skills and references solve different problems: skills move the model off the first default; references (and the rules for using them) decide where it lands. A skill with ban lists and no landing place produces the next default, which is what the cream/serif/terracotta wave looks like.
- The newest skill versions converge on the same structure regardless of author: a short written direction (plan, lock or contract) that is reviewed before any code, then a render check against it. Refero adds the only explicit rules for several references on top of that structure.
- Impeccable deliberately keeps a cited reference from dictating the look; that suits clients with no references but works against a designer whose references are the point. For reference-led work, Refero's rules fit better than Impeccable's.

### Gaps
- No independent, repeated-run evaluation of any skill; Velox is one run per skill by a vendor.
- No test of the Refero method against plain prompting with the same references.
- superdesign's and ui-ux-pro-max's skill files were not read directly; statements about them come from vendor blogs and listings.

## 4. Complaints and what people say fixed them

### Takeaway
Three separate failures are reported and they have different fixes: generic output (fixed by a concrete target: a reference, a token file, or named constraints), over-copying (caused by a single reference or a file with no instruction; fixed by saying what to take and what not to), and patchwork or blandness from several references (caused by unlabelled references being treated as equal; fixed by roles, one dominant source, and a reject list). A fourth, less noticed failure is "snap-back": the model follows the reference where it has one and returns to its default wherever it has to invent.

### Cited Findings

**Generic**
- **[SHOWN][SECONDHAND for figures]** Adrian Krebs scored Show HN landing pages against about 16 AI design patterns (covered by GIGAZINE on 23 Apr 2026); secondary write-ups report gradients on 28% of sites, untouched shadcn/ui on about 23.5%, 21% of sites with five or more patterns and 46% with two to four. Sample size is given as about 1,000 by Krebs and 500 by one write-up. — [Adrian Krebs](https://www.adriankrebs.ch/blog/design-slop/), [GIGAZINE](https://www.gigazine.net/gsc_news/en/20260423-design-slop)
- **[SHOWN]** Repaint: a paragraph of style adjectives is close to useless; images steer because a screenshot carries hundreds of small spacing, color and layout decisions. — [Repaint](https://repaint.com/blog/picture-is-worth-a-thousand-tokens)
- **[CLAIMED]** Muzli: name a concrete alternative (palette, radius, typeface) instead of a negative, because "don't use cream" fails; and reference cultural aesthetics (Swiss editorial, early-2000s zine) not other websites. A separate guide says the opposite, that explicit negative instructions beat positive revision requests **[SECONDHAND]**. The two conflict. — [Muzli](https://muz.li/blog/claude-design-one-week-in-hacks-best-practices-tips-from-real-world-use/), [MindStudio](https://www.mindstudio.ai/blog/build-design-system-claude-design-no-ai-aesthetics)
- **[SHOWN]** Claire Vo: a specific named aesthetic (a 1990s GeoCities page) worked where vague adjectives did not; visual references corrected an image model better than more words. — [ChatPRD](https://www.chatprd.ai/how-i-ai/claude-design-and-gpt-images-2-building-landing-pages-slides-and-brand-kits)
- **[CLAIMED]** blode.co (30 Apr 2026): study calm products directly (inspect elements, screen-record interactions, even un-minify their JavaScript to read animation logic), then cut decoration and replace default icons and fonts. — [blode.co](https://blode.co/writing/you-dont-have-to-make-ai-slop)

**Copying too closely**
- **[SHOWN]** Heyn Studio: with references attached and no words, one run copied a reference's card almost directly. — [DEV Community](https://dev.to/heynstudio/i-ran-the-same-claude-design-request-4-times-only-the-reference-hand-off-changed-4fnb)
- **[DOC]** v0: a bare screenshot is replicated; a few guiding words turn it into a loose reference. Figma Make says the same: state 1:1 or inspiration. — [Vercel Academy](https://vercel.com/academy/v0-foundations/enhance-design-with-screenshots-and-versions), [Figma Help](https://help.figma.com/hc/en-us/articles/31304529835671)
- **[DOC]** Mobbin's MCP guidance to agents: do not copy protected designs, branding, text or assets verbatim; adapt to the user's brand and constraints; look at several products, not one; a recurring pattern is a convention, not proof it is best. Updated 31 Oct 2026. — [Mobbin MCP](https://mobbin.com/mcp.md)
- **[CLAIMED]** Chase Hannegan names the "clone ceiling": a cloned site is a foundation, not a design. — [Chase AI](https://chaseai.io/blog/7-levels-building-elite-websites-claude-code)

**Patchwork, averaging, blur**
- **[SHOWN]** Heyn Studio: two unlabelled references were mixed at random; more than three references blurs the result even with roles. — [DEV Community](https://dev.to/heynstudio/i-ran-the-same-claude-design-request-4-times-only-the-reference-hand-off-changed-4fnb)
- **[DOC][VENDOR]** Refero describes the other outcome of unlabelled mixing: not collage but a bland middle, with red flags such as dark canvases turning cream, saturated accents turning muted, geometric sans turning polite serif, sharp corners turning soft cards, distinctive layouts turning into hero + sections. Its fix: a bold reference either stays bold or is rejected. — [anti-ai-slop.md](https://github.com/referodesign/refero_skill/blob/HEAD/skills/refero-design/references/anti-ai-slop.md)
- **[SHOWN]** SpecifyUI (Zhejiang University, arXiv 9 Sep 2025): in interviews with six practitioners, merging references was where designers struggled most; they wanted, say, layout from one image and feel from another but describing that in words was too much work, and models had no way to extract and recombine selectively. Their prototype breaks each reference into a structured spec (global: layout, color system with roles, shape language, usage; then page → section → component) and lets the user take color and shape from one reference, navigation and table from another, a widget from a third. Experts rated it above Google Stitch on style consistency (5.52 vs 4.18 of 7) and layout consistency (4.99 vs 3.73); 16 users typed about 73% less. It works best when the designer already has a clear goal. — [arXiv](https://arxiv.org/html/2509.07334v1)
- **[CLAIMED]** Gonsalvez uses "Frankenstein UI" for a different mix-up: several component libraries across screens. — [DEV Community](https://dev.to/stevengonsalvez/the-ai-design-stack-three-skills-and-a-workflow-that-stops-the-slop-5a07)
- **[SECONDHAND]** Image-generation guides explain blending the same way: models have no native way to treat each reference as a separate bounded instruction, so uploads merge into one averaged signal; the fix is to state which attribute comes from which image, and one strong reference beats five weak ones. These are about image models, not UI code. — [InVideo FAQ](https://invideo.io/faq/why-does-ai-blend-multiple-reference-images-instead-of/)

**Snap-back and false confidence**
- **[SHOWN]** Repaint: reference images are fragile; the model cannot reproduce complex layouts or animation, and when it has to fill in content the reference does not cover it snaps back to its default. Letting the model iterate alone cost about 20 minutes and $10, plateaued fast and missed an unreadable button. — [Repaint](https://repaint.com/blog/picture-is-worth-a-thousand-tokens)
- **[CLAIMED]** Chase Hannegan's "vibe gap": Claude Code gets the general feel of screenshots but misses the mechanics; picture-to-code is lossy. — [Chase AI](https://chaseai.io/blog/7-levels-building-elite-websites-claude-code)
- **[DOC]** Impeccable and Refero both add a compare-against-target gate because the agent's own judgment of its match is unreliable; Superdesign's prompt asks for a specific diff, not a general impression. — [new-work-comp.md](https://github.com/pbakaus/impeccable/blob/HEAD/.agent/skills/impeccable/reference/new-work-comp.md), [visual-workflow.md](https://github.com/referodesign/refero_skill/blob/HEAD/skills/refero-design/references/visual-workflow.md), [Superdesign](https://superdesign.dev/blog/claude-code-design-prompts)

**Tool-specific complaints**
- **[CLAIMED]** Claude Design: heavy usage burn (one user reported two sessions using 58% of a weekly Pro limit), no image generation, placeholder copy needs rewriting. — [Muzli](https://muz.li/blog/claude-design-one-week-in-hacks-best-practices-tips-from-real-world-use/)
- **[VENDOR][SHOWN]** Variant: from a blank prompt the variations are not very different; a reference-based dashboard had overlapping pills and padding errors, and fixing means re-rolling. (Review by a competitor.) — [Banani](https://www.banani.co/blog/variant-ai-review)
- **[SECONDHAND]** Reddit, as quoted by blogs: r/ClaudeAI users say the model plays safe and picks generic choices; asking for a button "like Stripe's dashboard" beats asking for a button. — [AIDesigner blog](https://www.aidesigner.ai/blog/claude-code-frontend-design)

### Inferences
- Patchwork (pieces of each reference side by side) and averaging (a bland middle) are two faces of the same cause: the model was not told which reference wins where. The first shows up when references are passed as images with no words; the second when the agent has "researched" several and synthesises by itself.
- A reject list is the cheapest protection against averaging, because it names the specific middle the model will drift to.
- Snap-back predicts where a blended page will look generic: in the sections none of the references covered. The direction therefore needs to say what happens in uncovered sections, not only in the hero.

### Gaps
- No first-hand Reddit or X threads; all such quotes are relayed by blogs.
- The "concrete alternative vs explicit negatives" conflict is unresolved; neither side shows a test.
- Nobody reports numbers on how often several references produce patchwork versus averaging.

## 5. Tools built for mixing references

### Takeaway
Tools that literally mix references exist (MagicPath's Mix, Variant's Style Dropper, image models that blend many inputs), but none publishes how the mix is controlled, and the only one with reported limits (Style Dropper) is described as a loose suggestion to a probabilistic model. The reference libraries wired to agents (Refero, Mobbin) frame mixing as research and synthesis, and only Refero gives the agent rules for it. Nothing was found connecting Cosmos, Savee or Pinterest boards to coding agents.

### Cited Findings
- **[VENDOR][CLAIMED]** MagicPath "Images on Canvas" (newsletter, 7 Dec 2025): drag images onto the canvas, select several and press Mix to explore new styles and variations, keep references beside components, @-mention them in chat; a GIF shows a landing page from two image references. How the blend works is not explained. Also a Chrome extension that captures live sites into editable frames **[SECONDHAND]**. — [Creators' Toolbox](https://creatorstoolbox.beehiiv.com/p/magicpath-releases-images)
- **[SECONDHAND]** Variant "Style Dropper" (Fast Company column by Jesus Diaz, 17 Feb 2026, read via a mirror): click one generated design, then another, and the first one's typography, spacing and palette are applied to the second. Criticisms: it only works on designs generated inside Variant (not a bitmap or a Figma file), and it is a visual suggestion to a probabilistic engine, so results are not predictable. — [Briefly mirror](https://briefly-prod.herokuapp.com/anchor/UX_design/story/this-new-ai-eyedropper-tool-brings-one-of-the-most-powerful-ux-tricks-into-the-ai-age), [Abduzeedo](https://abduzeedo.com/node/89056)
- **[VENDOR][SHOWN]** Variant's other controls are single-axis: Change Style, Shuffle Layout, Remix Colors, Vary Strong/Subtle; an earlier variation can be attached as a style reference. - **[DOC][VENDOR]** Refero MCP (paid plans; 8,000 tool calls a month): three layers searched separately — Styles for look, Screens for concrete UI patterns, Flows for multi-step journeys — and the skill tells the agent to take visual direction only from Styles and not to use Screens as the main source of aesthetics. — [Refero docs](https://doc.refero.design/mcp/getting-started.md), [SKILL.md](https://github.com/referodesign/refero_skill/blob/HEAD/skills/refero-design/SKILL.md)

- **[VENDOR]** Lazyweb's comparison page (updated Jun–Oct 2026) lists Lazyweb, Mobbin, Refero, Figr, Flowstep and UXPin and admits it rarely says how any of them combine references; library counts conflict between sources. — [Lazyweb](https://design.lazyweb.com/best/ai-design-research-tools)

No results shown; the references are generated, not the designer's own. — [MoodyBoards](https://moodyboards.ai/blog/moodyboards-claude-code-build-website.html)
- **[SHOWN]** SpecifyUI (research prototype, not a product) is the only system found that makes "style from this one, layout from that one" a first-class action. — [arXiv](https://arxiv.org/html/2509.07334v1)

- **[DOC]** Claude Design keeps several design systems to switch between, and Stitch's canvas takes images, text and code as context, but neither documents blending two systems or several images. — [Claude Help Center](https://support.claude.com/en/articles/14604416-get-started-with-claude-design), [Neowin](https://www.neowin.net/news/google-updates-stitch-with-vibe-design-and-infinite-ai-canvas/)

### Inferences
- Products treat mixing as a button with no dials; practitioners who get good results treat it as a written allocation. There is room for a tool that asks "what do you take from each?" and no shipping product was found that does it (SpecifyUI is research).

- Chase Hannegan's home-made brief-per-screenshot app shows the demand: designers want each saved reference to arrive with words attached.

- No documentation found on how MagicPath's Mix or Variant's Style Dropper work internally, and no independent test of either.

## 6. Write-ups from respected design engineers, studios and tool makers

### Takeaway
The named people agree on three things: set the look before generating, explore many options and let the human choose, and give the model something to see. They split on whether references should be other products at all: Refero and most practitioners say study real shipped work; Muzli's roundup says cite cultural aesthetics rather than websites; Impeccable keeps a cited product from setting the look. None of the well-known designers has published a tested method for several references; the detailed methods come from a tool maker (Refero) and a solo studio (Heyn).

### Cited Findings
- **[CLAIMED]** Nate Parrott, Anthropic (24 Jul 2026): without direction Claude picks a default look; supply fonts/colors or a mood board; bring real logos and assets because Claude Design has no image model; photograph a paper sketch when a layout is hard to describe; ask for ten, remix two. — [Claude blog](https://claude.com/blog/how-the-product-designer-who-built-claude-design-uses-it-to-explore-ideas-before-building-them)

- **[DOC]** Paul Bakaus, Impeccable: derive the look from the audience's own world, roll among candidates to break the agent's ranking habit, record a short contract, write DESIGN.md last, measure against the comp. — [new-work-world.md](https://github.com/pbakaus/impeccable/blob/HEAD/.agent/skills/impeccable/reference/new-work-world.md)

- **[CLAIMED]** Meng To, Aura / DesignCode (27 Jul 2025 interview; mostly paywalled): a prompt alone is not enough for great design; share examples, templates and assets; start from references and templates, not a blank prompt; use a prompt builder for layout, style and type; do the last 10% by hand. — [Behind the Craft](https://creatoreconomy.so/p/use-ai-to-create-beautiful-designs-meng-to)

## 7. How to hand references to the model

### Takeaway
The consistent advice is: few references (two or three, or one primary plus one or two narrow borrows), each with a stated job, each with a "take" and a "don't take", plus a line saying whether it is inspiration or a build target. A bare image is read as "reproduce this"; several bare images are read as equally binding. Beyond that, sources recommend turning each reference into words or tokens before the build, feeding sections rather than whole pages, and keeping a reject list.

### Cited Findings

### Inferences
- The hand-off that the evidence supports is a small table, not a pile of images: reference → the one thing it gives → what it must not give, plus a reject list and a line on what leads. Heyn Studio shows it working at two references; Refero specifies it for three or four.
- Because bare images are read as build targets, an assistant that fetches references itself should attach its own "why this one, for what" note to each before designing, and should show that note to the designer.
- Cropping to the detail fits "take only this from it": if only the color or one component is wanted, the model need not see the rest of the page at all. No source tests this directly; it follows from the role advice and Anthropic's zoom finding.

### Gaps
- No test of cropped-to-the-detail references versus whole screenshots for UI generation.
- No test of labelled images in one message versus one image per turn.
- The upper limit ("more than three blurs") rests on one author's runs; Refero's 3–4 is a rule in a skill, not a measurement.
- No guidance found on handing over motion references (video) for blending; Figma notes its agent cannot analyse video at all.
